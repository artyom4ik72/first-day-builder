# Архитектура 203 · first-day-builder

Одностраничное приложение React 19 + TypeScript, сборка Vite в статический сайт. Сервера нет. Проверка и экспорт — чистые функции в `src/core/`, интерфейс в `src/ui/` показывает их результат.

## Модули

| Модуль ТЗ | Файл | Ответственность |
|---|---|---|
| `plan-editor` | `src/ui/PlanEditor.tsx`, `src/App.tsx` | поля плана, контакты, блоки, порядок, сдвиг времени, замечания со ссылками на поля |
| `timeline-validation` | `src/core/timeline-validation.ts`, `src/ui/Timeline.tsx` | `validatePlan(plan) → { issues, overlaps, conflictIds, timed, untimed, links, ok }`, шкала дня |
| `plan-store` | `src/core/plan-store.ts`, `src/ui/usePersistentDraft.ts` | IndexedDB с ревизиями, файл черновика, резервная копия на `pagehide` |
| `html-export` | `src/core/html-export.ts`, `src/core/links.ts` | `renderPlanHtml(plan) → string`, экранирование, нормализация ссылок, CSP |

## Данные

```ts
DayPlan  { version: 1, date: 'YYYY-MM-DD', title, newcomer, mentor, welcome, blocks: Block[], contacts: Contact[], updatedAt }
Block    { id, kind: 'meeting' | 'task' | 'material', title, start: минуты | null, duration: минуты, parkedStart: минуты | null,
           place, description, link, contactIds: string[] }
Contact  { id, name, role, email, phone }
```

Время — минуты от начала выбранной даты, без часовых поясов. Дата словами («понедельник, 23 ноября 2026») строится без `Intl`, поэтому одинакова в любом браузере.

## Проверка

1. Поля: заголовок и дата плана, название блока, время встречи, начало в пределах суток, длительность от 1 минуты, конец не позже 24:00, ссылка, имя и почта контакта. Каждое замечание несёт ключ поля (`block.<id>.start`), по нему интерфейс подсвечивает поле и переводит к нему фокус.
2. Пересечения. Блоки со временем сортируются по началу, затем по длительности, затем по порядку ввода. Проход держит набор незакончившихся блоков: перед блоком `b` из набора убираются блоки с концом ≤ начала `b` (смежные допустимы), со всеми оставшимися `b` пересекается. Так длинная встреча 10:00–12:00 даёт конфликт и с 10:30–11:00, и с 11:15–11:45, хотя соседние по списку блоки не пересекаются. Блоки с ошибкой времени в проход не попадают. Юнит-тест сверяет результат с полным перебором пар на 300 случайных планах.
3. `ok = нет замечаний и нет пересечений`. Только тогда доступны предпросмотр и скачивание.

## Экспорт

`renderPlanHtml(plan)` вызывает `validatePlan`, берёт оттуда `timed` (порядок по времени), `untimed` (порядок редактора) и нормализованные ссылки и собирает одну строку HTML со встроенными стилями. Пользовательский текст проходит `escapeHtml` (`& < > " '`), переносы строк превращаются в `<br>` уже после экранирования. Ссылка: `href` — нормализованный адрес (`new URL`, punycode), подпись — то, что ввёл наставник, без схемы. В `<head>` CSP `default-src 'none'; style-src 'unsafe-inline'`: даже пропущенный тег не выполнится. Страница не обращается к сети.

Предпросмотр — та же строка в `<iframe srcdoc sandbox="allow-popups allow-popups-to-escape-sandbox">` (скрипты запрещены). Он обновляется через 300 мс после последней правки. Скачивание строит файл из текущего плана в момент нажатия.

## Нормализация ссылок

Пустая строка — нет ссылки. Схема, отличная от http/https (`javascript:`, `data:`, `file:`, `ftp:`), отклоняется. Адрес без схемы, похожий на домен (`wiki.example.com/x`), получает `https://`. Отклоняются пробелы, логин и пароль в адресе, адрес без домена (`https://intranet`).

## Хранение и состояния

`usePersistentDraft` повторяет схему проекта 208: чтение записи `current` из IndexedDB `first-day-builder` с блокировкой редактора на это время, запись через 300 мс после правки цепочкой `putIfRev`, `BroadcastChannel('first-day-builder')` для других вкладок, выбор «Оставить мою» / «Взять версию из другой вкладки» при чужой ревизии, синхронная копия в `localStorage['fdb.v1.unsaved']` на `pagehide`, работа в памяти при недоступной IndexedDB.

## Производительность

Блок получает ошибки и конфликты примитивами, поэтому `memo` пропускает неизменённые блоки. Предпросмотр обновляется с задержкой 300 мс: перезагрузка iframe на каждое нажатие давала длинные задачи. Замеры — `docs/ACCEPTANCE.md`, раунд 4.

## Решения и причины

- **Предпросмотр = файл.** Одна функция и один `DayPlan` исключают расхождение «в редакторе одно, у новичка другое». Это проверяет e2e: `srcdoc` iframe совпадает со скачанным файлом.
- **Без скриптов в выгрузке.** Странице не нужна интерактивность, а CSP закрывает целый класс ошибок экранирования.
- **Свёрнутые подробности блока.** Место, ссылка, описание и контакты свёрнуты (кроме материалов и полей с ошибкой): на телефоне план из 10 блоков иначе занимает 17 экранов.
