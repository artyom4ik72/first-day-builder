# Приёмка 203 · first-day-builder

## Как повторить проверки

```bash
npm ci
npm run typecheck
npm test                 # 13 юнит-тестов (Vitest)
npm run e2e:install      # один раз: Chromium для Playwright
npm run e2e              # 21 сквозной тест по dist/ (вложенный путь и корень)
npm run build && npm run e2e   # то же по свежей сборке
```

Замеры раунда 4 печатаются строками `PERF203 {...}` в выводе `npx playwright test e2e/perf.spec.ts`, высота страницы раунда 3 — строкой `PAGE203`.

## Сквозные сценарии (e2e)

| Файл | Что проверяет |
|---|---|
| `e2e/plan.spec.ts` | приёмка ТЗ (подсветка, перенос встречи, скачивание, отдельное открытие файла без сети, перезагрузка); два пересекающихся и смежные блоки; ссылки; HTML как текст в предпросмотре; раздел без времени и порядок; контакты; файл черновика |
| `e2e/recovery.spec.ts` | перезагрузка до записи; медленная и недоступная IndexedDB; две вкладки; правка во время конфликта; возврат прежнего времени |
| `e2e/a11y.spec.ts` | 360 и 320 px; высота страницы; широкий экран; замечания с названием блока; сценарий с клавиатуры и размер кнопок |
| `e2e/perf.spec.ts` | задержка ввода и перезагрузки предпросмотра на демо и на 60 блоках |
| `e2e/root-path.spec.ts` | та же сборка из корня сервера, все ресурсы 200 |

Скачанные файлы тесты сохраняют во временную папку с латинским путём: путь в `test-results/` содержит кириллицу из названия теста, а Chromium при локали POSIX такой путь не открывает. К приложению это не относится, имена файлов приложения только латиницей.

## Раунд 1. Правила и полнота продукта

**Что проверялось.** Каждый пункт ТЗ: дата, встречи, задачи и материалы, порядок блоков, контакты, ссылки, отдельная страница без доступа к редактору; время в минутах от начала даты; пересечения с учётом самой поздней границы предыдущих блоков; смежные встречи допустимы; материалы без времени отдельным разделом; один `DayPlan` для предпросмотра и экспорта; нормализация ссылок; длинная встреча с двумя вложенными конфликтами; HTML в подписи как текст.

**Ручной пример.** Демо: «Настройка ноутбука» 10:00–12:00, «Знакомство с командой» 10:30–11:00, «Получить пропуск» 11:15–11:45. Проверка только соседних блоков после сортировки нашла бы первый конфликт и пропустила второй: «Знакомство» кончается в 11:00, раньше начала «Пропуска». Алгоритм с набором незакончившихся даёт оба конфликта по 30 минут. Обед 12:00 начинается ровно в конце настройки, конфликта нет. После переноса настройки на 13:00 порядок в файле: 09:30, 10:30, 11:15, 12:00, 13:00, 15:00, 16:30.

**Диагностика.** Сверка поиска пересечений с полным перебором пар на 300 случайных планах — совпадение. E2e проверяет, что `srcdoc` предпросмотра побайтно совпадает со скачанным файлом, а сам файл открывается по `file://` без единого сетевого запроса.

**Найдено.** Подпись ссылки бралась из нормализованного адреса. Для `https://вики.пример.рф/Новичкам` новичок видел бы `xn--b1amah.xn--e1afmkfd.xn--p1ai/%D0%9D%D0%BE…`: punycode и %-коды вместо адреса.

**Исправлено.** `href` по-прежнему нормализованный, а подпись берётся из ввода наставника без схемы (`вики.пример.рф/Новичкам`). Если ввода нет, путь декодируется `decodeURI`. Добавлен юнит-тест. Моя первая версия этого теста ожидала неверный punycode, набранный вручную. Значение исправлено на вычисленное Node.

**Повторная проверка.** `npm test` — 13/13, `npm run e2e` — все пройдены.

## Раунд 2. Ошибки, данные и восстановление

**Что проверялось.** Перезагрузка до автосохранения. Медленная и недоступная IndexedDB. Повторное нажатие «Загрузить демоплан». Две вкладки и конфликт ревизий. Правка, пока висит выбор версии. Повреждённый и чужой файл черновика. Ссылки на несуществующие контакты в файле. Обратимость действий с временем.

**Проверено без дефектов.** Схема хранения перенесена из проекта 208 вместе с исправлением его раунда 2 (редактор заблокирован, пока черновик читается). Все сценарии восстановления 208 повторены для плана и прошли. Правка во время конфликта не теряется: «Оставить мою» сохраняет последнюю версию с этой правкой.

**Найдено.** Если отметить «Без времени» у задачи и снять галочку, задача вставала на 09:00, прежнее 15:00 терялось. То же при смене типа «встреча → материал → встреча». Случайный щелчок необратимо портил время, тест показал `09:00` вместо `15:00`.

**Исправлено.** У блока появилось поле `parkedStart`: снятие со шкалы запоминает время, возврат восстанавливает его вместе с длительностью. Поле сохраняется в черновике и файле. Добавлен e2e «снять и вернуть время».

**Повторная проверка.** `e2e/recovery.spec.ts` — 6/6, полный `npm run e2e` — все пройдены.

## Раунд 3. Удобство и доступность

**Что проверялось.** Ширина 1280, 360 и 320 px: горизонтальная прокрутка, высота страницы, где оказывается проверка. Сценарий с клавиатуры. Понятность замечаний. Высота кнопок и заголовков `<summary>`.

**Найдено.**
1. На 360 px с демопланом страница высотой 12 783 px, проверка и кнопка выгрузки на 12 408 px, это 17 экранов ниже первого блока. Пока наставник правит время, он не видит, остались ли замечания.
2. На широком экране 1280×800 панель проверки начиналась на 907 px: выше неё стояла шкала дня высотой около 600 px.
3. Замечание «Укажите название» не говорило, у какого блока.

**Исправлено.**
1. На ширине до 900 px внизу закреплена панель «Замечаний: 2 · Показать» или «План готов к выгрузке · К выгрузке». Кнопка переводит фокус на первое замечание или на «Скачать страницу».
2. Место, ссылка, описание и контакты блока свёрнуты в «Место, ссылка, описание и контакты» с краткой сводкой. Раскрыто у материалов и при ошибке в ссылке. Сетка полей блока плотнее (минимум 8,5 rem на поле вместо 11). Высота страницы на 360 px: 12 783 → 8 679 px (−32%).
3. Панель проверки стоит над шкалой дня, на 1280×800 видна без прокрутки.
4. Замечания начинаются с названия блока или контакта: «Блок 9: Укажите название».

**Проверено без дефектов.** Горизонтальной прокрутки нет ни на одной ширине. Фокус после добавления блока в его названии, после перестановки на той же стрелке, после удаления на «Вернуть», замечание переводит к полю. Кнопки и заголовки подробностей не ниже 40 px.

**Повторная проверка.** `e2e/a11y.spec.ts` — 6/6, полный набор — 20/20 на момент раунда.

## Раунд 4. Производительность и качество реализации

**Что измерялось.** 20 изменений поля подряд, время от события ввода до второго кадра (`input` → `rAF` → `rAF`), число перезагрузок предпросмотра и сумма длинных задач (`PerformanceObserver longtask`). Демо с открытым предпросмотром и максимальный план: 60 блоков (45 со временем), 30 контактов. Chromium headless, 2 ядра. У замера есть нижняя граница: два кадра ≈ 33 мс.

**До исправления (два прогона).**

| Случай | Медиана | p90 | Перезагрузок предпросмотра | Длинные задачи |
|---|---|---|---|---|
| демо, ввод имени | 34–37 мс | 42–47 мс | 12–15 из 20 | 0 мс |
| 60 блоков, ввод названия | 82–87 мс | 106–108 мс | 10–12 из 20 | 353–393 мс |

**Причина.** Каждое нажатие заново строило страницу, и iframe разбирал `srcdoc` целиком. Кроме того, `memo` у блоков не работал: каждому передавалась новая функция поиска ошибок, и все 60 редакторов перерисовывались.

**Исправлено.** Предпросмотр обновляется через 300 мс после последней правки, файл при скачивании строится из текущего плана. Блок получает ошибки и конфликты строками, и `memo` пропускает неизменённые блоки.

**После исправления (два прогона, те же условия).**

| Случай | Медиана | p90 | Перезагрузок предпросмотра | Длинные задачи |
|---|---|---|---|---|
| демо, ввод имени | 33 мс | 33–34 мс | 1 из 20 | 0 мс |
| 60 блоков, ввод названия | 33 мс | 34 мс | 1 из 20 | 0 мс |

33 мс — это граница замера (два кадра), реальная задержка может быть меньше. Проверка плана из 60 блоков (`validatePlan`) занимает доли миллисекунды и узким местом не была.

**Повторная проверка.** Полный `npm run e2e` — 21/21, `npm test` — 13/13. Тест приёмки по-прежнему подтверждает, что предпросмотр совпадает с файлом.

## Раунд 5. Воспроизводимость выпуска

**Что проверялось.** Установка строго по `package-lock.json` (`npm ci`), проверка типов, тесты, сборка, лицензии в `dist/`, отсутствие секретов и абсолютных путей, команды README из чистой распаковки ZIP.

**Результат в рабочей папке.** `npm ci`, `typecheck`, `test`, `build`, `e2e` проходят. `dist/THIRD_PARTY_LICENSES.txt` содержит лицензии `react`, `react-dom`, `scheduler`. Сборка открывается из корня и из вложенного пути. Абсолютных путей и секретов нет. Почтовые адреса в демо на зарезервированном домене `example.com`.

**Проверка архива.** Кандидат собирается `tools/package_release.py` и проверяется `tools/verify_browser_zip.sh` в чистой временной папке: обязательные файлы, `npm ci`, typecheck, тесты, установка браузера, e2e по `dist/` из архива, новая сборка, e2e по ней, HTTP-смоук двумя серверами. Протокол с размером и SHA-256 лежит снаружи архива: `verification/203-first-day-builder-*.md`.

## Известные ограничения

- Проверено только в Chromium. Firefox и Safari не запускались. Выгруженную страницу Chromium открыл по `file://`.
- Поле `type="time"` выглядит по-разному в браузерах. В Safari старых версий оно может принимать текст, тогда неверное время превращается в пустое и даёт замечание «Укажите время начала встречи».
- Порог в `perf.spec.ts` задан с запасом (медиана < 300 мс). Реальные числа смотрите в строках `PERF203`.
